# Child Wish Page

Follow the [master design system](../MASTER.md). Order: child identity -> primary wish -> other wishes -> at most one concrete rework hint. The full task area lives in Tasks; do not duplicate generic task/finance navigation here.

iPhone is natural in portrait and also supports landscape. iPad reflows with orientation/window dimensions. Use sidebar only in sufficiently wide/tall windows; otherwise bottom navigation. On the task page, wide windows can show five configured tasks in a row; narrow windows use three columns, very narrow two. Scroll rather than shrink text/targets. Retain each page's scroll during tab changes and reflow.

Wish progress uses confirmed accumulation, displaying target, confirmed amount, and gap. Never animate expected returns as owned money. Gift receipt and saving enough are separate. A funded gift still shows debt, and borrowing does not fill progress.

New wishes queue until explicit primary selection. Creation does not change cash. Real zero-onboarding should guide the first wish; never import the prototype's CNY 32.
